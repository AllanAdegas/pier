# Pier website

Launch page and user documentation, in Portuguese (pt-BR) and English. Static pages generated by Deno: the
content lives in `content/docs/`, the order, titles and descriptions in `src/pages.ts`, every other text in
`src/strings.ts`, and the version comes from `../internal/version/version.go`.

```sh
deno task serve     # builds dist/ and serves it at http://localhost:8080
deno task test      # tests, including links, anchors and the language pairs
deno task build     # only builds dist/
```

## The language rule

Every page exists in both languages, in the same change. CI (`deno task test`) and the build fail when an
English page is missing or does not match its Portuguese source.

| | Portuguese (source) | English |
| --- | --- | --- |
| Home | `/` | `/en/` |
| Documentation | `/docs/<pt-slug>/` from `content/docs/<pt-slug>.md` | `/en/docs/<en-slug>/` from `content/docs/en/<en-slug>.md` |
| Titles, descriptions, section names | `src/pages.ts` (`pt`) | `src/pages.ts` (`en`) |
| Header, footer, home, 404, button labels | `src/strings.ts` (`pt`) | `src/strings.ts` (`en`) |

Every page links to the same page in the other language and declares `hreflang` alternates (`x-default` is
English). The 404 page is a single page with both languages.

What the tests check for each pair:

- both files exist, and no file exists that `pages.ts` does not list;
- the same headings (`##`, `###`, … in the same order), the same code blocks (count and language label) and
  the same `{{placeholders}}`;
- no `#` title and no front matter in the body: the title and description come from `pages.ts`;
- the same internal links, rewritten to English: `/docs/backup/#redis-keydb-e-dragonfly` becomes
  `/en/docs/backups/#redis-keydb-and-dragonfly`, the anchor of the heading at the same position;
- no link leaves the page's language (only the language switch does);
- every internal link and anchor resolves in both languages; no placeholder is left unresolved;
- `strings.ts` has the same keys in both languages.

### Adding or changing a page

1. Write or edit `content/docs/<pt-slug>.md` (Portuguese).
2. Write or edit `content/docs/en/<en-slug>.md` with the same structure. Translate prose and the comments
   inside code blocks; keep commands, placeholders and code unchanged. Link to English pages
   (`/en/docs/<en-slug>/#english-anchor`); an anchor is the heading in lower case, without accents, with
   hyphens (`## 5. Put the panel on a domain with HTTPS` → `#5-put-the-panel-on-a-domain-with-https`).
3. For a new page, add one entry to `src/pages.ts` with `slug`, `title` and `description` in `pt` and `en`,
   at the same place in the reading order.
4. Run `deno task test`.

### While a translation is in progress

`SITE_ALLOW_MISSING_EN=1 deno task build` (or `deno task build --allow-missing-en`) renders a missing English
page from the Portuguese text, with a "Translation in progress" banner. It is for local development only: the
build and the tests refuse it when the `CI` variable is set, and CI never sets it.
`SITE_ALLOW_MISSING_EN=1 deno task test` runs the parity checks on the English files that exist.

## Markdown

Placeholders: `{{version}}`, `{{tag}}`, `{{repo}}` and `{{cliRepo}}`. An unknown placeholder or a broken
internal link fails the build.

## Hosting

`SITE_BASE_PATH=/pier/ deno task build` rebases every local link for a site served below a prefix (both
languages). Container image (from the repository root):

```sh
docker build -f site/Dockerfile -t pier-site .
docker run --rm -p 8080:8080 pier-site
```
